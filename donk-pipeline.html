TI2VA 策略模式

输入 文本 + 首帧图像 + 初始手-相机锚点 → 预测未来视频与双手动作。作动作策略。

T2VA 数据引擎模式

What it is

00核心定位与贡献类别

一句话：同一个视频-动作联合去噪器，给观测图像它就是灵巧手动作策略，不给图它就是数据引擎——靠训练时以 0.30 概率随机丢掉首帧图像条件，把这两种模式压进同一套主干、同一套 flow-matching 目标里（在 Wan2.2 TI2V-5B 上联合去噪视频 token + 双手 MANO 动作 token）。

用来干什么

  • ① 作动作策略（TI2VA）：从图像 + 语言预测未来双手 MANO 轨迹。
  • ② 作"数据引擎"（T2VA）：仅凭文本生成成对的"交互视频 + 同步手部动作"，把廉价的人类视频先验转成动作对齐的机器人训练数据——因为真实遥操作数据又贵又稀缺。

贡献属于什么类别（具体，非泛泛）

✓主要贡献

问题形式化 + 训练策略。首次把 T2VA（文本→成对视频+动作）当作灵巧操作的纯文本数据引擎，并用"随机丢图"这一训练技巧把策略模式和数据引擎模式统一进一个模型、一套损失。

~次要 / 明确不是

次要是轻量架构适配（视频保持型注意力掩码、零初始化门控锚点注入、轻量动作头），都是挂在冻结 Wan 上的适配器，不是全新架构；数据用现成 VITRA-1M，不是数据集贡献。

阅读约定：本文每一处都标注来源。绿色 事实 = 论文明确写出；琥珀色 推断 = 论文未给、需从工程常识推断或属未涉及范围。每节末尾附"事实 / 推断"对照盒。
Stage 01 · Data Collection

01数据采集

Donk 本身不采集新数据。训练唯一使用 VITRA-1M 数据集（引文 [33]，Qixiu Li 等，arXiv:2510.21571）。因此 Donk 的训练样本本质是第一人称 / 以人手为中心的人类操作视频，而非遥操作采集的机器人数据。

1.1 动机：为什么用人类视频替代机器人数据

论文反复强调这一逻辑：灵巧操作的"成对机器人视觉-动作轨迹"因遥操作、标定、精细动作标注困难而昂贵稀缺；而"大规模人-物交互视频 + 文本条件视频先验"廉价丰富。事实

1.2 VITRA-1M 的原始素材 vs 产出（关键澄清）

需要分清两层。VITRA 自带双手 MANO 轨迹与左右手语言指令是事实，而非推断——这正是 VITRA 那篇工作的核心产物。

原始素材无脚本、无标注的第一人称视频

Ego4D、Epic-Kitchens、EgoExo4D、Something-Something V2 等原片，长度与任务粒度不一，含无关 / 噪声动作，缺语言指令与 3D 动作标签。即原片什么标注都没有。

VITRA 产出全自动人类活动分析流水线的结果

把原片转成与机器人 VLA 数据对齐的格式：生成原子级手部活动片段及其语言描述，每段附逐帧 3D 手部运动（MANO 表示）与相机运动，最终得到约 100 万 episode、2600 万帧的 hand-VLA 训练数据集。

  • 语言指令：自带，且就是分左右手的子指令（"Left hand: … / Right hand: …"），与论文图 2 完全一致——分手指令直接来自 VITRA，不是 Donk 自己拆的。
  • 手部动作：自带逐帧 3D 手部运动，采用 MANO 表示（VITRA 数据卡片明确致谢 MANO 贡献者）。
  • 相机运动：自带（即 Donk 用到的相机内参 K 与首帧手部状态 s₀ 的来源）。

Donk 在此基础上仅做：对 MANO 轨迹归一化、对无效/缺失手掩码、渲染 anchor 图。底层"双手 MANO 轨迹 + 左右手语言"都是 VITRA 现成提供——这也呼应了"Donk 不是数据集贡献"的定性。

Stage 02 · Data Processing

02数据处理

从"原始样本"到"可喂入去噪器的训练张量"，共五个动作。其中图像条件注入 + 0.30 丢图是 Donk 能"一个模型两用"的工程根因。

2.1 视频编码

视频进入预训练 Wan VAE 潜空间。事实

$$x_\varepsilon = \mathcal{E}(V_{0:T})$$

2.2 动作表示

动作表示为归一化连续双手 MANO 轨迹；无效手维度在训练中掩码。事实

$$a_\varepsilon = A_{1:T}$$

2.3 锚点图渲染（首帧几何脚手架）

由 g₀=(s₀,K) 渲染一张彩色编码的 MANO 骨架图 M₀=R(g₀)，再用冻结 Wan VAE 编码成潜表示 m₀=E(M₀)。这张图给首帧提供"手在像平面的位置与姿态"的几何脚手架。事实

$$M_0 = R(g_0), \qquad m_0 = \mathcal{E}(M_0)$$
边界：g₀ 只是初始条件，不是未来轨迹——它告诉模型"开局手在哪儿、什么姿态"，后续手-物演化由联合去噪器自己学。

2.4 图像条件注入（关键统一技巧）

  • 当提供观测图像（Iε=I₀）时：把 VAE 编码后的首帧图像直接替换第一帧视频潜变量，并赋予时间步（timestep）0。
  • 当无图像（Iε=∅）时：跳过这一替换。

事实 注意区分：图像注入钳的是第一帧视频潜变量；anchor 注入（见 §4 架构）加的是第一帧的几何提示——二者是两条独立的首帧条件通路。

2.5 条件随机丢弃

训练时以 0.30 的概率丢弃 I₀，于是"有图（TI2VA）"和"无图（T2VA）"两种模式共享同一套主干、token 布局和目标函数。事实

✓本节事实
  • x_ε=E(V₀:T)，Wan VAE 潜空间编码。
  • a_ε=A₁:T，归一化双手 MANO，无效手维度掩码。
  • 锚点图 M₀=R(g₀) 为彩色编码 MANO 骨架图，冻结 Wan VAE 编码为 m₀。
  • 有图替换首帧潜变量 + timestep 0；无图跳过；训练 0.30 概率丢图统一两模式。
~本节推断 / 未明确
  • 锚点骨架图的具体配色 / 通道约定、MANO 渲染器实现细节。
  • 动作归一化的具体方案（按数据集统计的均值方差？坐标系？绝对 vs 相对）——只说"归一化"。
  • 逐帧手区如何得到（合理推断来自 MANO 渲染）。
Shared Backbone

03模型结构（训练 / 推理共享基础）

训练的输入输出与损失，必须放在这套结构上才能讲清。Donk 的结构是"挂在冻结 Wan 上的轻量适配"，而非全新网络。

3.1 去噪器基座

从 Wan2.2 TI2V-5B [12] 初始化，是一个视频扩散 Transformer（DiT [13]），在 flow-matching 范式 [14] 下联合去噪视频 token 与动作 token。事实

3.2 Token 拼接与新增模块

$$z = [\,z_{\text{video}},\ z_{\text{action}},\ z_{\text{anchor}}\,]$$

Wan 原生视频头预测视频输出；新增一个轻量动作头预测 MANO 动作；另加轻量动作编码器、状态编码器、anchor 编码器。事实

3.3 视频保持型联合注意力（Video-Preserving Joint Attention）

非对称掩码：视频 query 只能看视频 token；动作 / anchor query 能看全序列。这样视觉流计算尽量贴近预训练 Wan（不被新引入的动作/anchor token 扰动），同时动作 token 能"读"到正在生成的视觉 rollout 与初始手-相机锚点，实现手部运动与视频对齐而不牺牲视觉先验稳定性。事实

3.4 Anchor-Map 控制器（五步）

步骤 1共享控制表征

把 m₀ patch 化后送入轻量适配器 G_anc，得到共享 anchor 控制表征 C。

步骤 2分层提示

对每个被选中的 Wan 层 ℓ∈S，用该层专属 MLP 生成与首帧视频 token 同维的 anchor 提示 H_ℓ。

$$C = G_{\text{anc}}\!\big(\text{Patch}(m_0)\big), \qquad H_\ell = \text{MLP}_\ell(C), \quad \ell \in S$$
步骤 3门控首帧注入
$$z^{\text{video}}_{\ell,0} \;\leftarrow\; z^{\text{video}}_{\ell,0} + \gamma_\ell\, H_\ell$$
仅注入第一帧（t = 0）；t>0 的视频 token 保持不变——只改第一帧。
步骤 4门初始化为 0

γ_ℓ 初始为 0，所以训练从纯 Wan 行为起步，anchor 的影响随训练逐步学出来，不会一上来就扰乱预训练先验。

步骤 5T2VA 的初始化器

无图时没有真实 s₀，于是单独训一个轻量"文本条件初始化器"，学习首帧手-相机状态的经验分布以实例化 g̃₀；它只用于渲染 anchor 图，不参与未来视频/动作生成。

一点关系澄清：首帧手部状态 s₀ 有两个去处——既用来渲染 anchor 图，又被图 2 中独立的 State Encoder（消融表里的 "State" / state expert）编码成状态 token 作为条件。所以消融里 "State" 开关指的是这条状态编码通路，与 anchor 控制器相关但不是同一个东西。
✓本节事实
  • 基于 Wan2.2 TI2V-5B；DiT；flow-matching 联合去噪视频 + MANO 动作。
  • z=[z_video, z_action, z_anchor]；原生视频头 + 轻量动作头。
  • 视频保持型非对称注意力掩码。
  • 零初始化门控的首帧 anchor 注入，只作用于第一帧。
~本节推断 / 未明确
  • 动作 / 状态 / anchor 编码器与动作头、anchor 适配器的具体维度、层数（只说"轻量"，无数字）。
  • 被注入 anchor 的 Wan 层集合 S，以及训练时"解冻的一小部分 Wan 层"具体是哪些、有多少。
Stage 03 · Policy Training

04策略训练

单一训练配方，两种条件模式共用（靠 §2.5 的 0.30 丢图）。下面给出训练时的输入输出、四项损失、可训练范围与优化超参。

4.1 训练时的输入与输出

Inputs · 输入
  • 加噪的视频潜变量
  • 加噪的动作 token
  • anchor token
  • 文本嵌入
  • （有图时）干净的首帧图像潜变量
  • 初始手部状态 s₀
Outputs · 预测目标
  • 视频速度 v̂_x
  • 动作速度 v̂_a

分别用 flow-matching 目标 v_x, v_a 监督。

4.2 损失函数（四项 · 论文事实）

① 视频流匹配 + ② 掩码动作流匹配

$$\mathcal{L}_{\text{video}} = \lVert \hat v_x - v_x \rVert_2^2, \qquad \mathcal{L}_{\text{action}} = \frac{\lVert M_a \odot (\hat v_a - v_a) \rVert_2^2}{\max\!\big(\textstyle\sum M_a,\ 1\big)}$$
M_a 屏蔽无效手维度；分母 max(∑M_a, 1) 做归一化以防全掩码时除零。

③ 注视 / 手部聚焦视频损失 L_gaze

一个手部聚焦的视频损失，做法是对渲染手部区域附近的视频流误差加权，强调手-物交互区。可理解为：在标准视频误差 ‖v̂_x−v_x‖ 上，按"是否靠近手区"做空间重加权，手区权重更高。事实（概念）

命名易误导：名字 "GAZE / gaze" 容易让人以为是注视/眼动，但论文描述的是手部区域加权，不是真的视线追踪。

④ 教师先验 L_prior

用一个冻结的 Wan 教师模型，喂给它相同的视频潜变量与文本条件，让它预测视频速度 v̂_xtea；约束学生视频速度向教师靠拢，稳定视觉生成路径（防止新加的动作/anchor token 拉低画质）。事实

$$\mathcal{L}_{\text{prior}} = \lVert \hat v_x - \hat v_x^{\,\text{tea}} \rVert_2^2$$
关键细节：L_prior 只在保留图像条件时启用。因为图像是通过钳制第一帧潜变量注入的，教师在"有图"时是被图像 grounding 的；若在纯文本分支也启用，等于逼一个没有图像的分支去模仿一个用了图像的教师——不合理，故只在有图时加。

总目标

$$\mathcal{L}_{\text{Donk}} = \lambda_v\big(\mathcal{L}_{\text{video}} + \lambda_g\,\mathcal{L}_{\text{gaze}}\big) + \lambda_a\,\mathcal{L}_{\text{action}} + \lambda_p\,\mathcal{L}_{\text{prior}}$$
注意 L_gaze 被 λ_v·λ_g 共同加权。动作与 anchor 接口（含 anchor-map 适配器）端到端随此目标训练。

4.3 可训练 vs 冻结

Frozen · 冻结
  • 文本编码器
  • VAE
  • 教师模型
  • 绝大多数 Wan 块
Trained · 训练
  • 动作 / anchor 接口
  • anchor-map 适配器
  • 动作头
  • 一小部分 Wan 层

T2VA 的额外组件：单独训练一个轻量"文本条件初始化器"，学习首帧手-相机状态的经验分布以实例化 g̃₀；它只用于渲染初始 anchor 图，不参与未来视频/动作生成。事实

Stage 04 · Deployment & Inference

05部署推理与控制

两种推理模式共用同一去噪核。重点是把"控制到底怎么发生"的边界讲清——这关系到能否把 Donk 当真机策略看待。

5.1 TI2VA（策略模式）

输入 (c, I₀, g₀)，其中 g₀ 来自观测到的首帧手部状态与相机内参。用 I₀ 钳制（clamp）第一帧视频潜变量，然后去噪生成未来视频-动作轨迹。事实

$$p^{\text{policy}}_\omega\big(V_{1:T},\,A_{1:T} \,\big|\, c,\, I_0,\, g_0\big)$$

5.2 T2VA（数据引擎模式）

只输入文本 c。初始化器先实例化一个合理的 g̃₀ 并渲染 anchor 图，再用同一去噪器生成成对的交互视频 V₀:T 与同步 MANO 动作 A₁:T。事实

$$p^{\text{engine}}_\omega\big(V_{0:T},\,A_{1:T} \,\big|\, c,\, \tilde g_0\big)$$

5.3 推理时冻结

文本编码器、VAE、教师、绝大多数 Wan 块。事实

5.4 "控制"到底怎么发生（关键边界）

Donk 的"动作"输出是双手 MANO 轨迹（腕部位姿 + 手指 MANO 参数）。所谓"作为策略"是指：给定当前观测图像与指令，模型一次性预测一段时域 T 的未来双手动作 chunk。

!必须明确的范围限制

论文对它的评测全部是离线开环——把预测 chunk 与真值轨迹比对（OakInk2 / EgoDex），没有任何闭环执行、没有真实机器人控制实验。这一点是事实

因此以下属于推断 / 未涉及：

  • 如何把人手 MANO retarget 到具体机器人手（跨形态映射）——论文未做、未讨论。
  • 闭环重规划频率、动作执行接口——未涉及。
  • T2VA"数据引擎"的下游闭环（生成数据 → 训下游策略 → 证明性能提升）在本文并未跑通；结论明说这只是"迈向把 WAM 直接当数据引擎的初步路径（initial path）"，其有效性仅以生成质量佐证，而非下游任务收益。
✓本节事实小结
  • TI2VA：(c, I₀, g₀) → 用 I₀ 钳第一帧潜变量 → 生成未来视频-动作。
  • T2VA：仅 c → 实例化 g̃₀ + 渲染 anchor 图 → 同一去噪器生成成对视频-动作。
  • 评测均为离线开环对真值，无闭环、无真机。
