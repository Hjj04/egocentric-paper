一句话定位：DreamDojo 是一个视频世界模型 —— 给它当前画面 + 一串动作，它"脑补"出未来视频。核心做法是先用海量人类第一人称视频学物理，用"潜动作"绕开人类视频没有动作标签的难题，再在小规模目标机器人数据上微调，最后蒸馏成实时自回归模型。整条管线分三阶段：

PHASE 01
人类视频预训练
In-lab + EgoDex + DreamDojo-HV，潜动作作统一条件
PHASE 02
目标机器人后训练
重置动作层，小规模真机数据全量微调
PHASE 03
蒸馏
转成因果自回归、few-step，实时 10.81 FPS
01
Data Collection & Composition

数据采集与组成成分

DreamDojo 的预训练完全建立在第一人称（egocentric）人类视频上，而非传统遥操作机器人数据。立场是：人类与机器人在交互时底层物理一致，因此知识可跨 embodiment 迁移。

1.2 额外的机器人数据

事实

In-house 机器人数据集 Unitree G1、Fourier GR-1、AgiBot、YAM 不参与人类视频预训练，而是用于：(a) 训练潜动作模型；(b) 作为 post-training 的目标 embodiment；(c) 构建评测集。

1.3 动作标签从哪来？自带还是额外处理？

分两类看：

  • 事实 文本任务描述 — 数据自带（采集/众包时人工标注）。
  • 事实 真正喂给世界模型的动作条件 — 主要靠额外处理得到。In-lab 自带 Manus 手姿（需 retarget 成 GR-1 动作）；EgoDex 自带 3D 手指姿态（论文又转成 MANO）；占 98% 的 DreamDojo-HV 完全没有动作标签，只有文本。因此论文统一改用潜动作（latent action），由一个自监督模型从相邻两帧自动算出，给所有视频打"代理标签"。
推断

In-lab 由 Manus 手姿 retarget 到 GR-1 的具体重定向管线、众包数据的清洗/质控流程、文本标注的具体 schema，论文均未展开。

1.4 数据可得性（现状）

现状 · 截至 2026-06，须以官方为准

据官方 GitHub 仓库更新日志，已放出的是：预训练+后训练代码、全部 2B/14B 权重、GR-1 后训练数据集、评测集。那 44k 小时的 DreamDojo-HV 预训练大语料并未放出，下载不到（仓库 "Datasets" 链接指向的是 GR-1 遥操作后训练集，不是预训练语料）。三块里只有 EgoDex 是 Apple 的独立公开数据集可单独获取；In-lab(55h) 与众包主体(43.8k h，98%) 不开源。常见原因（推断）：隐私/肖像、众包同意书范围、PB 级分发成本。

02
Data Processing

数据处理

事实

处理环节的关键操作如下：

  • 时间降采样（temporal downsampling）= 跳帧。按随机因子 {1,2,3,4} 抽帧：因子 1 全取（原速）、因子 2 隔一帧取一帧（2× 快进），以此类推。目的：原视频相邻帧动作差异极小，跳帧后让相邻帧动作幅度变大、节奏更多样，使潜动作模型覆盖从慢到快的运动。主要服务于潜动作模型训练。
  • 空间分辨率：潜动作模型用 320×240；世界模型用 640×480（均 center crop + resize）。注意它与时间降采样是两回事（一个砍帧、一个砍像素）。
  • 序列切片：预训练/后训练切成长度 13 的序列。
  • 相对动作（relative action）：不用绝对关节位姿，而以每个 latent frame 起点（即每 4 个 timestep）的位姿做 rebaseline 转成相对动作。理由：相对动作分布更窄、跨轨迹共享，降低建模复杂度、增强泛化。
  • 动作分块（chunking）：WAN2.2 tokenizer 时间压缩比为 4（一个 video latent xi 对应像素空间连续 4 帧），故把连续 4 个动作 at:t+4 拼成一个 chunk，注入对应 latent frame。

补充：动作分块到底在管什么？（常见疑问）

输出确实是视频帧；分块管的是输入端动作条件如何对齐与屏蔽，两个作用：① 对齐粒度 —— 让"4 动作一块"正好对上"1 latent frame = 4 画面帧"；② 遵守因果、防偷看未来 —— 若把整条动作轨迹当全局条件喂给所有 latent frame，模型算前面帧时会"看到"未来才该发生的动作，造成因果混淆；分块让每个 latent frame 只看它该看的那 4 个动作。实验 (Table 5) 证实加 chunked injection 后 PSNR 明显上升。

03
Policy / Model Training

策略训练（三阶段）

3.0 骨干：Cosmos-Predict2.5

事实

世界模型本体基于预训练的 Cosmos-Predict2.5（latent video diffusion + DiT），在 WAN2.2 tokenizer 的连续潜空间中运作，用 flow matching 训练。架构并非从零设计。语言经 cross-attention 注入，timestep 经 sinusoidal→MLP→adaptive layer norm 调制。

Eq. 1 · 世界模型定义st+1  ~  p( · | st, at )
Eq. 2 · flow matchingLflow(θ) = E ‖ u(xt, t, c; θ) − vt ‖²  ,  vt = ε − x

两处架构改进（基于骨干）

  • 事实 相对动作变换（见 §2）：降低建模复杂度，增强对连续/组合动作的泛化。
  • 事实 分块动作注入（见 §2）：缓解因果混淆，提升可控性。

3.1 阶段一 · 人类视频预训练

核心难题（事实）：人类视频没有细粒度动作标签。直接被动预测未来帧能迁移部分物理，但缺乏因果性，迁移到机器人后交互性差。

解决方案：连续潜动作作为统一 proxy

事实

训练一个潜动作模型（VAE + 时空 Transformer，Genie 风格），带 information bottleneck：Encoder 取相邻两帧 ft:t+1 → 提取时空特征 → 投影到低维 embedding ât；Decoder 用 ât + 前一帧 ft → 预测下一帧 ft+1。瓶颈强迫模型 disentangle 出关键动作信息。不用 HaMeR/MANO 等现成手姿提取器的理由：它们只能描述手、表达不了手臂与移动、遮挡/相机运动下不稳、且 embodiment gap 大时迁移差。

Eq. 3 · 潜动作 VAELpred = Eq[ log p(ft+1 | â, ft) ] − β · DKL( q(â | ft:t+1) ‖ p(â) )
输入 / Input
人类视频帧序列（长 13）+ 每个 latent frame 上 chunk 化的潜动作条件 + 空文本 prompt（事实：文本固定为空）
输出 / Output
预测的未来视频帧（去噪速度场 velocity）
  • 事实 潜动作经 lightweight MLP 投影到 timestep embedding 维度；MLP 最后一层零初始化（ControlNet 式），避免训练初期扰动预训练权重，经验上改善 physics；再与 timestep embedding 相加，喂入每个 DiT block 的 adaptive layer norm。
  • 事实 数据采样比 In-lab : EgoDex : DreamDojo-HV = 1 : 2 : 10。

训练目标：加入时间一致性损失

事实 标准 flow matching 单独监督每帧、忽略时间相关性。论文加一项匹配相邻帧速度差的损失，加速学动作可控性、增强物体完整性、减少 artifacts。

Eq. 4 · 时间一致性Ltemporal = E [ Σi=1K−1 ‖ (zi+1 − zi) − (vi+1 − vi) ‖² ]
Eq. 5 · 最终目标Lfinal = Lflow + λ · Ltemporal  ,  λ = 0.1

3.2 阶段二 · 目标机器人后训练

事实

把目标机器人的真实动作 flatten 成序列，整段过 action MLP；重新初始化 action MLP 第一层 以匹配目标动作空间，然后全量 finetune 所有预训练权重。靠强预训练，目标机器人数据可在有限域、小规模采集仍达 zero-shot 泛化。

输入 / Input
长 13 序列；第一帧为条件帧；原始动作处理成长 12 的相对动作 chunk（目标机器人真实动作）
输出 / Output
目标机器人在该动作下的未来视频帧

3.3 阶段三 · 蒸馏（Self Forcing）

事实 目的：实现自回归 + 实时。瓶颈：双向注意力固定 horizon、去噪步数太多（如 50）。基于 Self Forcing，把 teacher Gteacher 蒸馏成 student Gstudent：同架构同权重，但双向注意力→因果注意力、步数缩到 few-step（如 4）、滑窗 12 帧。

① Warmup 阶段

student 用 teacher forcing（上下文来自 teacher 生成的 latent），回归到 teacher 的 ODE 解。

Eq. 6 · warmupLwarmup = E ‖ Gstudent(xt, t) − x0 ‖²   (x0 来自 teacher ODE 轨迹)

② Distillation 阶段

student 改用自己之前生成的 latent 作上下文，对齐训练/推理分布、减少 compounding error；用 distribution matching loss（teacher/student 的 KL）。为对抗长程误差累积，让 student 生成 N′ > N 帧（N 为 teacher horizon），随机选大小 N 的窗口接收梯度。

Eq. 7 · 分布匹配Ldistill = DKL( pteacher ‖ pstudent )
Eq. 8 · 梯度∇Ldistill = − E [ ( sreal(xt,t) − sfake(xt,t) ) · dGstudent/dθ ]

sreal 由 Gteacher 估计，sfake 由训练在 Gstudent 输出上的模型估计。

推断

方法部分未给死 N、N′ 的具体取值（实验部分"训练时随机生成 13–49 帧、对最后 13 帧算 loss"可视作对应实现）；sfake 那个 "fake diffusion model" 的训练细节较略。

04
Deployment & Inference

部署与推理 · 如何控制

事实

推理设置：teacher 用 35 步去噪；蒸馏后 student 用 4 步；关闭 CFG（经验上收益有限）。student 最终在 640×480、10.81 FPS 自回归预测任意长度，连续交互 >1 分钟不退化。

世界模型输入
条件帧（student 可多帧上下文）+ 动作条件（相对动作 chunk）
世界模型输出
未来视频帧（自回归续帧）

"控制"= 改变喂进去的动作条件。三种下游用法对应三种控制方式：

4.1 Live Teleoperation · 实时遥操作

事实

在装 RTX 5090 的本地桌面跑 DreamDojo-2B，接 PICO VR 控制器捕捉 G1 机器人的上半身动作输入，实时遥操作"虚拟机器人"。通俗：给机器人做了个超写实电子游戏，你直接在游戏里操控它，零硬件损耗。

推断

VR 控制器输出如何实时转成模型需要的相对动作并 chunk 注入的完整工程管线，论文未给。

4.2 Model-based Planning · 在线规划

事实

集成 5 个训练 checkpoint 生成有方差的动作 proposal → 送进 DreamDojo 预测未来视频（用 distilled 2B 批量处理）→ 一个外部 value model 打分 → 选最优 proposal 由机器人执行。通俗：像下棋先在脑子里推演几步、挑最有利那步走。

推断 / 附录细节

value model 基于 DINOv2，取 4 帧 clip，DINOv2 backbone 冻结、独立提每帧特征，再经 global-attention 的 value head，估计到下一个子任务边界（相邻子任务语言标注间的关键帧）的剩余步数，按数据集最大子任务间隔归一化；滑窗 stride 1，选 value 最低（最接近完成）的 proposal 执行。value model 的训练数据具体来源/规模较略。

4.3 Policy Evaluation · 策略评估

事实

用相同初始帧让世界模型整段模拟一条 ~80s rollout，人工按真实世界相同标准打成功率，作为真机的替代评估器。通俗：给机器人策略做"虚拟考试"，分数与真机高度一致，从而靠它筛选 checkpoint。

三者共同点：把"必须在真机上试错"换成"在模型里试错" —— 这正是世界模型对机器人最大的价值。

5.1 贡献归类（具体而非空泛）

  • 数据集（最主要、最硬）：DreamDojo-HV / 整体 44,711 h，迄今世界模型预训练规模最大、最多样的人类视频语料。
  • 训练策略（核心方法）：以连续潜动作作跨 embodiment 的统一动作条件，解决人类视频无标签的迁移难题；配套"预训练→后训练→蒸馏"三阶段配方。
  • 训练/架构小改进（非全新架构）：相对动作 + 分块注入 + 时间一致性损失。
  • 蒸馏管线：在 Self Forcing 上做到实时自回归（10.81 FPS）并以短上下文改善长程一致性与抗遮挡。

真正"新"的集中在 数据规模 + 用潜动作打通"人类视频→机器人世界模型"的训练配方；骨干、潜动作、蒸馏框架都是在 Cosmos-Predict2.5、AdaWorld、Genie、Self Forcing 等已有工作上的组合与扩展。
